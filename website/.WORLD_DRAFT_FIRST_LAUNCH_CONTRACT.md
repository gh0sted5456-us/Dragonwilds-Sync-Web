# Dragonwilds Sync — Website Draft First-Launch Contract

> **Authoritative application/website compatibility note.**
>
> This file defines what Dragonwilds Sync must do after importing a browser-authored `.rsdwl` Website Draft. It is intentionally hidden from public website navigation.

## 1. Draft is a lifecycle state, not a new package type

Do not invent another `.rsdwl` package type.

The browser continues to export the existing v3 Website Draft envelope:

```json
{
  "format": "dragonwilds-sync-launcher",
  "version": 3,
  "packageType": "profile",
  "security": {
    "trustMode": "website-draft"
  },
  "metadata": {
    "websiteDraft": true
  }
}
```

After restricted validation/import, the desktop application creates a normal local World profile but marks it as incomplete setup state.

Recommended local-only state:

```json
{
  "draft": {
    "source": "website-builder",
    "state": "setup-required",
    "imported_at": "<UTC ISO timestamp>",
    "setup_completed_at": null,
    "last_setup_step": "review",
    "included_world_save": true
  }
}
```

This local `draft` object is application state. It does not grant authority and does not need to be published to the public directory.

## 2. Draft states

Supported local lifecycle values:

```text
setup-required
setup-in-progress
ready
```

Optional failure/recovery state:

```text
setup-attention
```

Do not use `running`/`stopped` as draft states. Runtime state remains separate.

## 3. Imported World card behavior

Immediately after import, create the World/profile card so the user can see what they built.

The card must visibly show:

```text
DRAFT
Finish setup before first launch
```

The user may inspect/edit presentation, Rules, Mods, artwork, release channel, and other safe draft metadata before setup is complete.

A draft must not silently start a dedicated server, publish itself, open Remote Admin, or register directory authority.

## 4. Guided first-launch trigger

The same guided setup flow must open when any of the following occurs while `draft.state != ready`:

```text
user clicks Finish Setup
user opens the draft World for first-time setup
user clicks Start Server
user clicks Launch / Play where that action requires the World to be materialized
application resumes an interrupted draft setup
```

Do not create separate wizards for import and first launch. Resume one persisted setup journal/state machine.

## 5. Wizard steps

The wizard should adapt to World type but use this order where applicable.

### Step 1 — Review browser draft

Show:

```text
World name
World type
Main / Experimental release channel
public/private intent
region
platforms
community rule profile
UE4SS / RuneSchema / PAK mod counts
artwork included/not included
World save included/not included
```

Allow Back/Edit without losing imported data.

### Step 2 — Server/runtime location

For Dedicated Server intent:

```text
Use existing dedicated-server install
or
Install / select dedicated-server location
```

Resolve SteamCMD and dedicated-server AppID through the application's existing authoritative install/update systems.

Do not store browser-originated absolute paths.

### Step 3 — World save

If the draft includes a World save:

```text
validate staged payload
show source summary/size
choose Apply included save
or Start as new World
```

If no save is included:

```text
Attach existing World save…
or
Create/start a new World
```

The application owns extraction, staging, backup, validation, and atomic promotion.

### Step 4 — Runtime/mod prerequisites

Based on normalized mod groups/runtime intent:

```text
UE4SS required/not required
RuneSchema required/not required
PAK content present/not present
```

Offer installation/verification through existing authoritative runtime systems.

Do not infer successful installation merely because the website draft listed a mod family.

### Step 5 — Networking

Review and normalize:

```text
game port
sync port
server number/instance number
LAN broadcast
public/private publication intent
firewall/router guidance where applicable
```

Generate safe defaults locally.

### Step 6 — Local authority and security

Generate locally:

```text
new profile ID
server_key
share_access_key
Remote Admin/WebGUI credentials when/if user enables them
operator/publication identity as required by the application
```

Never adopt authority/secrets from the Website Draft.

### Step 7 — Publication and Remote Server Manager

Ask separately whether to enable:

```text
public directory listing
WebGUI / Remote Server Manager
world-save distribution
```

These are explicit opt-ins and remain separate trust domains.

### Step 8 — Final review

Show a concise readiness checklist:

```text
World save ready
Dedicated runtime ready
UE4SS ready (if required)
RuneSchema ready (if required)
Mods staged
Ports assigned
Credentials generated
Publication choice recorded
Remote Admin choice recorded
```

Primary action:

```text
Finish Setup
```

Optional final actions after completion:

```text
Finish & Start Server
Finish Without Starting
```

## 6. Completion semantics

Only after all required checks succeed:

```text
draft.state = ready
draft.setup_completed_at = now
```

The World becomes a normal application-managed World.

The draft provenance may be retained for audit/history, but the `DRAFT` badge disappears from normal presentation.

## 7. First Start Server behavior

If the user clicks Start Server before setup completion:

```text
Start Server
↓
detect draft.state != ready
↓
open/resume Finish Setup wizard
↓
complete required steps
↓
explicit final confirmation
↓
Runtime Manager starts server
```

Never bypass the wizard by creating missing defaults silently during `Start Server`.

## 8. Resume and recovery

Persist wizard progress after each completed step.

If Dragonwilds Sync closes/restarts during setup:

```text
reopen World
↓
show DRAFT / Setup incomplete
↓
Resume Setup
```

If a long-running install/update fails, preserve prior successful steps and mark the draft `setup-attention` with the failed step/error.

Do not delete the imported draft merely because setup failed.

## 9. Editing after import

Changes made in Desktop/WebGUI during draft setup become authoritative local profile changes.

The original browser draft remains provenance only.

Do not re-import the Website Draft over those edits automatically.

## 10. World-save replacement safety

An included save is staged under the new World profile and applied only through application-owned safe operations.

Never:

```text
write directly into a running World
replace an existing save without backup/confirmation
extract ZIP members outside staging root
trust browser path names blindly
```

## 11. Public-directory behavior

A draft must not broadcast as a live public World until setup is completed and the user explicitly enables publication.

If the UI chooses to preview the card locally, use local-only status such as:

```text
DRAFT
NOT PUBLISHED
```

Do not send draft status to the public telemetry Worker as if the World were online.

## 12. Acceptance tests

Required tests:

```text
import Website Draft with save -> DRAFT card -> wizard opens -> save staged -> setup completes -> optional start succeeds
import Website Draft without save -> DRAFT card -> attach/new choice -> setup completes
click Start Server on incomplete draft -> wizard opens instead of starting
close app midway -> restart -> Resume Setup continues at persisted step
UE4SS/RuneSchema requested -> readiness step appears
no mod runtimes requested -> irrelevant runtime steps collapse/skip
public requested in browser -> still requires explicit local publication confirmation
Remote Admin requested/visible in browser metadata -> still requires local credential setup
malicious unsigned package not matching website-draft gate -> rejected
setup failure -> draft preserved with setup-attention
successful completion -> DRAFT badge removed; provenance retained
```

## 13. User-facing terminology

Website:

```text
Save Draft (.rsdwl)
```

Desktop import:

```text
Import World Draft
```

World card before setup:

```text
DRAFT
Finish setup
```

Wizard title:

```text
Finish World Setup
```

Do not call a Website Draft a fully configured/running server before local setup is complete.
