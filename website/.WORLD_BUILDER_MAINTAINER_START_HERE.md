## Mandatory compatibility instruction

Do not create a second incompatible World Builder schema.

The browser produces an **untrusted Website Draft `.rsdwl`**. The desktop application validates it through a dedicated restricted import path, creates a new local World profile and fresh secrets, stages any included World save safely, and creates that World in **DRAFT / setup-required** state.

A Website Draft is visible and editable after import, but it is not runnable yet. Opening it for setup, clicking `Finish Setup`, clicking `Start Server`, or first-launching it must open/resume the same persisted **Finish World Setup** wizard. Only after required local runtime, save, networking, credential, publication, and security checks pass does the application change the draft to `ready` and allow normal runtime control.

Rules and Mods are shared structured World metadata:

```text
community_rule_profile
community_rules (legacy compatibility projection)
mod_groups.ue4ss
mod_groups.runeschema
mod_groups.paks
```

When rendering `mod_groups.ue4ss` or `mod_groups.runeschema`, all application surfaces must resolve the family through the canonical registry/preset data and display the authoritative bundled artwork rather than maintaining a surface-specific icon.

Browser-selected World icon/banner artwork is different from website theme artwork: selected World artwork may be packaged into the Website Draft and safely staged by the Desktop importer. It must preview locally without upload and must remain visible through live placard re-renders. The receiving app owns the final persisted location.

World banners use the shared placard visual contract: fill the header, remain readable in the upper/central area, and fade/blend into the permanent dark placard body. Desktop, WebGUI, standard placards, horizontal placards, and browser previews should preserve that same presentation semantic.

Platform compatibility is shared structured metadata too. New application/WebGUI work should normalize Nintendo compatibility to:

```text
switch2
```

while continuing to read legacy Website Draft/profile values such as:

```text
nintendo
nintendo switch
switch
```

as Nintendo Switch 2.

The **Public Server Directory is a merged Cloudflare response**, not a Sync-only webpage and not a browser-side scraper. External public observations may be shown as limited `PUBLIC SERVER` placards, but whenever the Worker strongly identifies one as the same underlying World as a signed Sync heartbeat, only the Sync World is published. Exact endpoint is a strong identity signal; a route-less source may use unique exact World name + exact build. World name alone must never auto-merge into a Sync World. Ambiguous records stay separate.

The public-provider refresh model is **resumable full scanning**, not a fixed 100- or 500-entry snapshot. The Shrug adapter advances a bounded cursor across five-minute cron runs and preserves the previous generation until the new scan reaches the provider's terminal page. LobbySup consumes its complete returned set as one generation. `PUBLIC_SOURCE_MAX_SERVERS` exists only for the older fallback refresher and must not be treated as the authoritative directory size.

The website Server Directory must offer both `Placards` and `Horizontal` views over the same filtered records. The webpage must render every record returned by the Worker. Do not reintroduce an arbitrary website display ceiling.

The public page publishes `website/directory-source.json`. The human URL:

```text
https://gh0sted5456-us.github.io/Dragonwilds-Sync/servers.html
```

may be pasted into the Desktop `Public Server List`. The Desktop resolves it to the canonical read-only Cloudflare feed and displays the same merged/deduplicated roster. This is discovery presentation only: it does not grant Sync trust, publication rights, World passwords, WebGUI sessions, admin credentials, or remote-control authority.

Desktop, WebGUI, public descriptors, website placards, focused placards, `.rsdwl` import/export, ecosystem mod-family chips, storefront actions, World artwork handling, and public-directory identity resolution must converge on the normalized registries/contracts rather than maintaining separate copies, substitute artwork, arbitrary URLs, or incompatible presentation rules.
