# Dragonwilds Sync — UE4SS / RuneSchema Ecosystem Logo Compatibility Contract

> **Authoritative maintainer note for AI/human implementation.**
>
> This note applies to Desktop, WebGUI/WebHost, the World Builder, public/focused placards, `.rsdwl` profile/draft presentation, documentation previews, packaging, and release validation.

## 1. Exact artwork is authoritative

The project owner supplied the canonical UE4SS and RuneSchema artwork directly.

The authoritative repository assets are:

```text
renderer/assets/platforms/ue4ss.webp
renderer/assets/platforms/runeschema.webp
```

These are lossless WebP encodings of that exact supplied artwork.

Do not redraw, trace, recolor, invert, simplify, substitute, or fetch alternate copies from a CDN.

Older files:

```text
renderer/assets/platforms/ue4ss.svg
renderer/assets/platforms/runeschema.svg
```

are legacy compatibility assets only. New code must not select them as the canonical art.

## 2. Shared registry authority

All surfaces should resolve ecosystem-family artwork through shared data rather than their own hard-coded icon maps.

Primary registry:

```text
resources/platform-registry.json
```

World Builder preset metadata:

```text
resources/world-builder-presets.json
```

Canonical mappings:

```text
ue4ss      -> ue4ss.webp
runeschema -> runeschema.webp
paks       -> paks.svg
```

The stable serialized family IDs remain:

```text
ue4ss
runeschema
paks
```

Artwork filenames are presentation metadata. `.rsdwl` drafts/profiles should serialize stable family IDs and mod-group contents, not user-controlled arbitrary icon paths.

## 3. World Builder

The browser World Builder must show the exact UE4SS and RuneSchema artwork on the mod-family selectors and any family detail chips.

Current browser enforcement:

```text
website/ecosystem-assets.js
```

The World Builder may load preset data from:

```text
assets/world-builder-presets.json
```

but if fallback data is used, the canonical registry still wins for built-in family artwork.

The builder must continue exporting structured groups:

```text
mod_groups.ue4ss
mod_groups.runeschema
mod_groups.paks
```

Do not encode the artwork itself into the World Draft as user authority.

## 4. Desktop application

Desktop must resolve built-in mod families using the canonical bundled registry/assets.

Wherever the application shows:

- runtime/mod-family selectors
- World/profile summaries
- placard Rules/Mods detail chips
- sync review screens
- server setup/Finish World Setup
- mod inventory/category summaries

it must use:

```text
UE4SS      -> renderer/assets/platforms/ue4ss.webp
RuneSchema -> renderer/assets/platforms/runeschema.webp
```

A missing built-in canonical logo should fall back to the text label and log a verification error. It must not download an arbitrary replacement.

## 5. WebGUI / WebHost

WebGUI/WebHost must expose or copy the same packaged canonical files and resolve the same family IDs.

Do not maintain separate hand-drawn WebGUI versions.
Do not convert the canonical artwork with theme CSS filters.
Do not invert the UE4SS white mark for light/dark themes; instead place it on a suitable bounded surface if contrast is required.

## 6. Placards and public directory

Public and focused placards may show UE4SS / RuneSchema / PAKs as clickable mod-family chips.

The chip icon is presentation-only and must come from the trusted bundled artwork.

A public World may declare that it uses the `ue4ss` or `runeschema` family, but it cannot supply a replacement built-in logo URL/path.

## 7. Theme behavior

The artwork itself is immutable across Dark Graph, White, and Liquid Glass.

Allowed:

- sizing
- padding
- bounded background behind a logo
- `object-fit: contain`
- normal opacity when disabled only if the entire control is disabled

Not allowed:

- `filter: invert(...)`
- grayscale as a normal presentation state
- recoloring the image pixels
- tracing into a theme-colored SVG
- replacing the supplied art with text initials when the bundled art exists

## 8. Packaging and deployment

Packaged Desktop/WebGUI builds must include:

```text
renderer/assets/platforms/ue4ss.webp
renderer/assets/platforms/runeschema.webp
```

GitHub Pages copies `renderer/assets/platforms/` to:

```text
_site/assets/platforms/
```

Website deployment/release checks should treat missing or zero-byte canonical ecosystem logos as failure.

## 9. Backwards compatibility

Do not break older code/data that identifies families by stable IDs:

```text
ue4ss
runeschema
paks
```

If an old UI hard-codes `ue4ss.svg` or `runeschema.svg`, migrate it to registry resolution or the canonical `.webp` asset. Legacy SVGs may remain temporarily only to avoid breaking an older packaged build during migration.

Once repository-wide verification confirms no active consumer requires the legacy SVG files, they may be retired in a dedicated cleanup change.

## 10. Required verification before release

Verify all of the following:

```text
ue4ss.webp exists and is non-empty
runeschema.webp exists and is non-empty
platform registry maps UE4SS to ue4ss.webp
platform registry maps RuneSchema to runeschema.webp
World Builder shows exact UE4SS art
World Builder shows exact RuneSchema art
public placard UE4SS chip shows exact art
public placard RuneSchema chip shows exact art
Desktop mod-family UI shows exact art
WebGUI mod-family UI shows exact art
Finish World Setup uses the same family IDs and art
no built-in family accepts an arbitrary remote icon URL
no normal theme filter recolors/inverts the canonical images
`.rsdwl` continues to serialize family IDs/data rather than trusted asset paths
```
