# Dragonwilds Sync — World Builder Platform / Store Compatibility Contract

> **Authoritative maintainer note for AI/human implementation.**
>
> Read this together with `website/.WORLD_BUILDER_MAINTAINER_START_HERE.md`, the Website Draft `.rsdwl` contract, and the first-launch Draft contract before changing World Builder platform compatibility, placard platform badges, WebGUI platform presentation, or storefront links.

## 1. One canonical bundled platform registry

Use:

```text
resources/platform-registry.json
```

as the shared platform/store metadata contract.

Bundled artwork remains under:

```text
renderer/assets/platforms/
```

Do not introduce separate Desktop/WebGUI/website copies as independent sources of truth.
Build/deploy outputs may copy these files, but the repository source remains canonical.

## 2. Nintendo Switch 2 is the canonical Nintendo target

RuneScape: Dragonwilds targets **Nintendo Switch 2**.

New normalized platform key:

```text
switch2
```

Canonical asset:

```text
renderer/assets/platforms/switch2.svg
```

Display label:

```text
Nintendo Switch 2
```

Recognized aliases include:

```text
switch2
switch 2
nintendo switch 2
nintendo switch2
```

The earlier World Builder/browser schema already used:

```text
nintendo
```

for the Nintendo toggle. Do **not** break those browser drafts or existing profiles.

Treat these older values as legacy aliases:

```text
nintendo
nintendo switch
switch
```

and normalize them to:

```text
switch2
```

when the Desktop application or WebGUI hydrates a World.

The website may continue serializing the legacy `nintendo` boolean in v1 Website Drafts until a coordinated schema revision is made. Its UI must nevertheless display **Nintendo Switch 2** and use `switch2.svg`. A future Website Draft schema revision may emit `switch2` directly, but the application must continue reading `nintendo` indefinitely for backwards compatibility.

## 3. Platform compatibility in `.rsdwl` Website Drafts

Website Draft platform data is capability/presentation intent, not proof that a runtime is installed.

Example normalized target:

```json
{
  "platform_compatibility": {
    "steam": true,
    "windows": true,
    "xbox": true,
    "playstation": true,
    "switch2": true,
    "epicgames": true
  }
}
```

Legacy input:

```json
{
  "platform_compatibility": {
    "nintendo": true
  }
}
```

must normalize as if:

```json
{
  "platform_compatibility": {
    "switch2": true
  }
}
```

Do not expose arbitrary icon paths or arbitrary storefront URLs inside `.rsdwl` user data.

The application resolves normalized platform keys through the trusted bundled registry.

## 4. Desktop application requirements

The Desktop application must use the same canonical meanings as the World Builder.

For every World/profile:

```text
serialized platform key
↓
normalize aliases
↓
canonical key
↓
trusted registry
↓
bundled logo + display label + optional trusted store URL
```

The application must:

- display Nintendo Switch 2 with `switch2.svg`
- read legacy `nintendo` as Switch 2
- never display a broken-image placeholder when a trusted logo is missing
- retain a text label as fallback
- never fetch normal platform artwork from a CDN
- never trust a World/profile to supply an arbitrary store URL
- keep native/full-color brand artwork; do not globally invert/grayscale/recolor brand SVGs

Where a platform badge is clickable, it may offer an **Open Dragonwilds Store** action using the trusted registry URL.

Opening a store link is a user-initiated external-browser action. It is not server/runtime authority.

## 5. WebGUI requirements

WebGUI/WebHost must resolve the exact same normalized keys and assets.

It must not maintain separate mappings such as:

```text
PS5 -> some-other-playstation-file.svg
Nintendo -> generic emoji
Xbox -> remote CDN URL
```

Required behavior:

- `psn`, `ps5`, `playstation` -> `playstation`
- `xbox series x|s`, `xbox live`, `xbox` -> `xbox`
- `nintendo`, `switch`, `nintendo switch` -> `switch2`
- `nintendo switch 2`, `switch2`, `switch 2` -> `switch2`
- `epic`, `epic games`, `epicgames` -> `epicgames`
- `win`, `win32`, `win64` -> `windows`

WebGUI must serve trusted SVGs locally from the Dragonwilds Sync host and preserve their native colors.

## 6. Website footer storefront rail

The public website may show a footer rail containing full-color platform/store logos.

Each icon must be an explicit external link to the trusted RuneScape: Dragonwilds product/store page for that storefront.

Current trusted storefront destinations are maintained in `resources/platform-registry.json` for:

```text
Steam
Epic Games Store
Xbox
PlayStation 5
Nintendo Switch 2
```

Do not build the destination from World telemetry.
Do not let a public World override a store URL.
Do not use referral/affiliate redirects unless explicitly approved later.

The footer icon must:

- use the baked local SVG
- preserve full color
- include an accessible label/tooltip
- open only after explicit user click
- use `noopener noreferrer` when opening a new tab

## 7. World Builder UI requirements

The browser World Builder platform picker must visually expose the actual supported Dragonwilds targets.

At minimum:

```text
Steam
Windows
Xbox
PlayStation 5
Nintendo Switch 2
Epic Games
```

Nintendo must display **Nintendo Switch 2**, not a generic Nintendo/Switch label.

The Switch 2 selector must use:

```text
assets/platforms/switch2.svg
```

The existing v1 Website Draft may still serialize its old `nintendo` field for compatibility as described above. This is intentional compatibility behavior, not a signal to keep the old UI label.

## 8. Store links and World Builder Draft trust boundary

Storefront URLs are trusted application metadata and must remain outside user-controlled World authority.

A Website Draft may contain platform compatibility booleans/keys, but must not be allowed to inject:

```text
store_url
platform_store_url
icon_url for built-in platforms
javascript: URLs
file:// URLs
custom executable launch URLs
```

The Desktop application/WebGUI/website resolves the store destination only from the trusted registry.

## 9. Footer and placard behavior are separate

A platform selected for a World placard communicates compatibility/availability intent for that World.

The website footer store rail communicates **where RuneScape: Dragonwilds itself is available/wishlistable**.

Do not infer one from the other.

Example:

```text
World placard supports: Steam + Windows
Website footer still shows: Steam + Epic + Xbox + PlayStation + Switch 2
```

Do not close platform compatibility work until all of these pass:

```text

Nintendo Switch 2 is visible in World Builder
legacy nintendo drafts import as switch2
Switch 2 placard badge resolves to switch2.svg
Desktop uses switch2.svg
WebGUI uses switch2.svg
Steam logo loads full color
Epic logo loads full color
Xbox logo loads full color
PlayStation logo loads full color
Switch 2 logo loads full color
footer store icons load from local assets
footer Steam link opens Dragonwilds Steam page
footer Epic link opens Dragonwilds Epic page
footer Xbox link opens Dragonwilds Xbox page
footer PlayStation link opens Dragonwilds PlayStation page

no World/profile can override trusted store URLs

```
