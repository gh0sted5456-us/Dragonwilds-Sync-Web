Core model

Small files. Explicit behavior.

The 0.6.1E work focused heavily on deterministic composition and safe runtime identity so multiple mods can coexist without relying on filesystem luck.

01

Deterministic mods

mods.txt controls enable state and load order. Later matching writes apply predictably after earlier ones.

02

Runtime assets

Patch supported assets, clone ItemData into genuinely separate items, or create supported reflected DataAssets and Curves.

03

Persistent rules

Author player profiles and persistent spawn behavior with stable selectors, baselines, scaling, attributes, and reflected properties.

Authoring areas

Assets, tables, and recipes

/assets handles reflected asset edits and runtime items, /raw can add or edit DataTable rows, and /recipes can register authored outputs at selected stations and categories.

Runtime areas

Players and spawns

/players supports persistent profile rules, attributes, appearance, and connection selectors. /spawns adds persistent actor/AI controls, names, scale, drop tuning, and component-level reflected properties.

Stable or Experimental?

Stable is the established loader baseline. Experimental adds authoring features that need in-game testing and the matching UE4SS runtime. The 0.6.1E changelog is a historical milestone; newer experimental packages may be available on GitHub.
