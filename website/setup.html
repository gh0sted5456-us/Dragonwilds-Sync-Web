01 · Start here

The mental model

Dragonwilds Sync is an organizer, synchronizer, launcher, and optional hosting/administration layer around RuneScape: Dragonwilds. Dragonwilds still owns the actual game session. Sync owns its own Profiles, managed files, synchronization manifests, dedicated-server supervision, and optional discovery/admin services.

PROFILELocal organization

A durable container that keeps one World’s save association, mods, runtimes, settings, cached metadata, backups, and presentation together.

SYNCVerified file agreement

The client compares authenticated manifests and hashes, stages changed managed content, verifies parity, and leaves unrelated local content alone.

GAME CONNECTIONActual Dragonwilds play

After preflight and synchronization, DragonLink-Connect hands the verified route and World type to Dragonwilds.

PUBLIC / REMOTESeparate trust surfaces

Public discovery, Sync transfer, game traffic, and Remote Admin are separate capabilities with separate authority.

Four different questions: Can I discover the World? Can I synchronize the World’s managed files? Can I join the Dragonwilds session? Can I administer the host? A “yes” to one does not imply the others.
02 · Windows

Initial setup on Windows

  1. Download the current Windows Portable EXE from the Downloads page or GitHub Releases.
  2. Place it in a writable folder you intend to keep. Dragonwilds Sync is portable; the stable Windows package is not an installer-style deployment.
  3. Run the launcher and complete Guided Setup. Select the real RuneScape: Dragonwilds installation rather than copying a path from another computer.
  4. Let Sync validate the retail game layout, discover saves/characters, and build the managed client baseline when required.
  5. Create or adopt the World/Profile you actually want to use, then manage its mods and runtime selections through that Profile.
Client loader safety: the dedicated-server bootstrap version.dll is server-only. It is not part of the normal retail/Proton client baseline.
03 · Linux

Initial setup on Linux

The stable Linux desktop package is the Ubuntu AppImage. It can be run directly, or organized with an AppImage manager such as Gear Lever. Linux hosting and Proton gameplay are deliberately treated as different runtime roles.

  1. Download the current Ubuntu AppImage and mark it executable, or import it into Gear Lever.
  2. Run Sync and point it at the actual Steam library, Proton-backed client, or dedicated-server root used by this machine.
  3. Let the launcher validate the path before adopting it. Native Steam, Flatpak Steam, secondary libraries, and dedicated-server roots can all differ.
  4. For a native Linux dedicated host, keep Linux UE4SS/RuneSchema material classified as server-only. Windows and Proton players receive the independently verified Win64 client runtime instead.
Do not copy a Linux server loader to Windows clients. V3 tracks platform and distribution policy per managed file specifically to prevent that class of cross-platform overwrite.
04 · File locations

Finding the right file paths

The best path is the one your platform already knows. Use Steam’s Installed Files/Storage UI or the SteamCMD install root you explicitly chose. Sync also provides path validation and Open Folder actions so you do not have to memorize fragile locations.

05 · Profiles

What a Profile is — and is not

A Dragonwilds Sync World/Profile is a computer-side organization boundary. It is not a Steam account, website login, Dragonwilds lobby, or public-directory registration. The launcher uses it to remember which save, character, mods, configs, runtime choices, backups, routes, and cached metadata belong together.

Why Profiles matter

Without Profiles, every modded or hosted setup competes for the same folders. With Profiles, “Main World,” “Vanilla Test,” “Building Sandbox,” a Connected friend’s World, and a Dedicated host can keep independent managed state.

  1. Create a new World/Profile or adopt/import an existing one.
  2. Name it for the environment it represents.
  3. Associate the correct save/game/server path and preferred character where applicable.
  4. Select the mods, runtime flavor, and distribution choices that belong to it.
  5. Launch, synchronize, reset, restore, or back up through that Profile so ownership remains explicit.
User Profile vs World Profile: your display name/avatar/banner are presentation identity. World Profiles are file/runtime organization. They are separate on purpose.
06 · Join a World

Connecting to Worlds

V3 supports LAN discovery, Direct Connect, saved Connected Worlds, and the public server directory. Public Server List owns discovery; saved Connected/Favorite entries own durable local profiles. A public listing is sanitized metadata, not a credential handoff.

  1. Select or discover the intended World and verify its identity/route.
  2. If the World requires a password or private synchronization information, enter it through the launcher’s protected connection flow.
  3. Sync refreshes the authenticated manifest, compares fingerprints, downloads only changed managed payloads, stages rollback-safe changes, and verifies parity.
  4. DragonLink-Connect receives the profile-scoped verified address, optional password, and synchronized World type, then prepares the matching Dragonwilds connection mode.
World password vs Sync authentication: the game’s World password and Sync’s file/authentication exchange serve different purposes. The launcher does not replace Dragonwilds’ own gameplay authentication.
07 · Dedicated hosting

Setting up a server

A Dedicated World owns a server installation, server configuration, runtime choices, managed mods, backups, process state, synchronization listener, and optional public/remote services. Existing installations and SteamCMD-managed installations are both supported workflows.

  1. Create or adopt a Dedicated World and choose the authoritative dedicated-server root.
  2. Validate the installation and configuration. SteamCMD is used only for the dedicated-server ownership path; retail Dragonwilds remains Steam-owned.
  3. Choose the server-side UE4SS/RuneSchema runtime and mods. Imported archives expose per-entry client-push selectors so server-only files remain on the host.
  4. On Windows server layouts, the dedicated bootstrap version.dll belongs in the server Binaries/Win64 deployment beside dwmapi.dll; the corresponding client baseline intentionally excludes version.dll.
  5. Start the World. Sync verifies the real dedicated process and the Sync/file-share listener before publishing it as healthy.
Operational rule: publication follows verified runtime state. Before stop, update, or destructive runtime mutation, presence is withdrawn so the directory does not advertise a World that is being taken down.
08 · Quick & Headless

Run the right pipeline with less UI

Quick Start and Headless Start are not separate configuration systems. They target saved Profiles and invoke the same authoritative local, Connected, or Server pipelines as the full launcher.

QUICKFocused graphical launcher

Useful when you already know which Profile you want and do not need the full management workspace.

HEADLESSTerminal/server operation

Useful for SSH and low-resource hosts after the Server Profile has been configured and verified.

Keep headless artifacts version-matched with the profile/application release that created the server state. Do not use a random older binary against a newer profile and assume compatibility.

09 · Networking

Connection and port-forwarding basics

Do not forward every port you see in the application. Each service has a different job, and several can remain LAN-only. Use the Network tools to test the exact route you intend to expose.

SERVICEDEFAULT / CONTRACTWHAT IT DOES
Direct Connect discovery / World Finder queryUDP 8422IP-first discovery/query path used by Dragonwilds Sync. This is UDP, not TCP.
Sync transferTCP 27051 + instance offsetAuthenticated manifest and managed-file transfer for Sync-compatible Worlds.
WebHost / Remote AdminTCP 27080 by defaultOptional separately authenticated web-management surface. Keep disabled unless you need it.
Dragonwilds gameplayGame/server configurationThe game’s own traffic. Treat this separately from the Sync helper services above.

Router checklist

  1. Reserve a stable LAN address for the host when practical.
  2. Forward only the services you actually intend to expose, using the correct protocol. In particular, World Finder/Direct Connect discovery uses UDP 8422.
  3. Allow the same protocol/port through the host firewall.
  4. Test from outside the LAN. NAT loopback can make an internal test misleading.
  5. If the ISP uses CGNAT, traditional inbound forwarding may not work; use an appropriate VPN/tunnel or externally reachable host instead.
10 · Public discovery

Broadcasting a World

Broadcasting is opt-in. A hosted Sync World can publish sanitized metadata to the Cloudflare-backed public directory after ownership and runtime checks succeed. The public website and launcher read that directory; they do not receive admin credentials.

  • Published data may include World identity, sanitized description, status, platform, route metadata, player counts, classifications, badges, mod/runtime summaries, and other explicitly public presentation fields.
  • World passwords, Secret Store material, Remote Admin passwords, and private management authority are not published.
  • Normal, Hard Mode, Creative, Custom, and additive PVP classification metadata can appear as World badges where available.
  • Public presence and public reachability are separate: a World can publish healthy metadata even while a user’s router/firewall path still needs repair.
Before you broadcast: verify the name, description, player limits, region/country choice, game mode/classification, public route, mods, and any user-facing rules you intend strangers to see.
11 · Remote administration

Remote login, WebHost, and WebGUI

Remote Server access is a separate opt-in security surface for the active hosted/broadcast World. It is not granted by appearing in Public Server List.

WEBHOSTSeparate listener

Runs on its own configured address/port and can remain LAN-only if remote Internet administration is not needed.

REMOTE USERSScoped permissions

Use named/scoped Remote Admin users instead of sharing one all-powerful credential.

WEBGUIAuthenticated controls

Provides supported server actions, responsive preview, audit history, and CSRF-protected management.

PUBLIC DIRECTORYRead-only discovery

Never inherits Remote Admin authority or credentials from WebHost.

Use HTTPS-capable network boundaries/tunnels where appropriate, keep the WebHost port closed when unused, and treat Remote Admin credentials like server credentials—not like a shareable invite code.

12 · Heartbeat telemetry

What the heartbeat actually does

A heartbeat is a small signed presence update sent by a hosted Sync World to the directory service. It proves that the publisher still controls that World identity and refreshes the public record. It is not gameplay traffic and it is not the file-transfer stream.

  • The heartbeat is renewable and supervised while the World should be public.
  • Ownership-sensitive actions such as invite creation or deregistration depend on the publisher identity rather than a public visitor.
  • Stale presence can expire instead of remaining permanently “online.”
  • Passwords and Remote Admin secrets are excluded from public heartbeat data.
  • Transient heartbeat/listener failures are supervised so the launcher can recover without rewriting unrelated World state.
13 · Mods & runtimes

What is in the default experience

The default managed experience is intentionally a runtime baseline, not a surprise gameplay mod pack. Dragonwilds Sync can install, verify, repair, reset, and select supported loader/runtime channels, then each World/Profile explicitly owns the mods it wants.

FAMILYROLE IN V3
UE4SSSupported runtime/mod-loader family. Sync manages baseline/stable/experimental/named/imported runtime choices and role-aware deployment.
RuneSchemaSupported data/mod-loader family. Sync manages runtime choices, archive inspection, load order, manifests, repair/reset, and profile assignment.
PAK contentManaged mod-content family with profile ownership, hashing, inventory, distribution policy, and rollback metadata.
Gameplay modsNot silently enabled just because Sync is installed. Mods are imported/discovered and then assigned to the appropriate World/Profile.

Client vs server files

Every distributable file can carry role/platform/distribution metadata. CLIENT/BOTH payloads may be pushed when the World requires them; SERVER_ONLY or distribution: never material stays on the host. Downloaded/imported archives expose file-level client distribution selectors so you can see exactly what will cross the network.

Generated mods.txt files are local. Sync derives a client-appropriate list from verified roles instead of copying the server’s literal file to every player.
14 · Troubleshooting

When something does not connect

  1. Confirm the Profile. Make sure you are repairing the intended World, not another cached/saved environment.
  2. Confirm the path. Open the configured game/server folder from Sync and verify it is the authoritative install.
  3. Read the synchronization stage. Connecting, comparing, downloading, unpacking, applying, verifying, profile, and ready failures point to different problems.
  4. Check the protocol. Direct Connect discovery is UDP 8422; Sync transfer is TCP 27051 plus instance offset; WebHost is a separate TCP service.
  5. Check public vs direct reachability. A directory heartbeat can be healthy while a router/firewall still blocks the direct route.
  6. Use Reset & Resync / Game Restore carefully. These remove tagged managed payloads, preserve game/EOS/save data, and rebuild the selected runtime baseline instead of blindly wiping the installation.
  7. Use logs and failure tails. Redacted diagnostics, Runtime Console sources, network evidence, and actionable recovery messages are designed to narrow the failing layer.
