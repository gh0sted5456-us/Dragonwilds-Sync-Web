RuneSchema

0.6.1E Experimental

Changes since 0.6.0

RuneSchema 0.6.1E expands item authoring, player profiles, persistent spawning, configuration, and deterministic multi-mod behavior while retaining the established RuneSchema loader layout.

Deterministic load order$Patch · $Clone · $CreateNew DataTable rowsPlayer profilesPersistent spawns
Deterministic mod management
  • Added RuneSchema/mods/mods.txt as the authoritative mod enable and load-order file.
  • Added 1 and 0 enable states for individual mod folders.
  • Added automatic mods.txt creation, optional folder reconciliation, comment preservation, and optional strict state validation.
  • Added control-panel actions for enabling, disabling, and reordering mods.
  • Mod folders now load in deterministic mods.txt order; files inside loader folders load in stable sorted-path order.
  • Matching changes from later mods and files are applied predictably after earlier changes.
Expanded configuration and tools
  • Expanded config/config.json with automatic reload, debug logging, experimental spawn drop scaling, authoring tools, JSON Schema generation, FModel snippet generation, mods.txt management, and compatibility-report settings.
  • Expanded the control panel with Overview, Settings, Generators, Load Order, and Compatibility sections.
  • Added optional compatibility reports for mods writing to the same assets, properties, or arrays.
  • Added broader generated JSON Schema coverage, FModel-oriented authoring helpers, and normalized Unreal object paths.
/assets — deterministic $Patch
  • Added the exact-case $Patch and $Target envelope with deterministic recursive merging of nested objects.
  • Patch results follow deterministic mod/file order; later matching field writes win predictably.
  • Identity fields cannot be changed through $Patch.
  • Nested $Patch, $Clone, and $Create directives are rejected.
  • Incomplete, empty, or malformed patch envelopes fail safely.
/assets — new-item $Clone
  • Added exact-case $Clone for ItemData assets, constructing genuinely separate runtime items.
  • Supported reflected properties are copied while transient, editor-only, instanced, deprecated, and unsafe identity state is excluded.
  • Authored fields apply after source properties are copied.
  • Clones require unique InternalName and canonical PersistenceID; source identity cannot be retained or aliased.
  • New items register with the native item subsystem and remain discoverable by authoring path, runtime path, object name, internal name, and persistence ID.
  • Authoring-path aliases allow recipes and supported references to resolve runtime-created items.
/assets — $Create, extended data, and consumable packs
  • Added exact-case $Create for supported reflected DataAsset and Curve classes with deterministic runtime object paths.
  • Item creation requires explicit permanent identity fields; Blueprint-class creation remains owned by /blueprints.
  • Supported reflected item fields include name/flavor text, icon/world mesh, equipped meshes, equipment slot, skill references, power level, durability, weight, tags, audio tags, drop/break behavior, buff presentation, and granted effects where supported.
  • Nested reflected structs, arrays, sets, maps, enums, text, objects, and soft references continue to use native reflected Unreal types.
  • Added normalized $ConsumablePack authoring with concise Drops and native ItemsToDrop spellings.
  • Runtime-created item references are supported; pack application waits when a referenced runtime item is not yet registered.
  • Ambiguous simultaneous pack/native-drop fields are rejected, and unsafe direct mutation of baked live emitter arrays remains blocked.
/raw
  • /raw can add genuinely new DataTable rows as well as edit existing rows.
  • New item assets can point row handles at newly authored rows.
  • This supports independent wearable-equipment values for Defense, Melee resistance, Ranged resistance, Magic resistance, and Maximum vital shield.
  • Row structures and values remain governed by the native cooked DataTable schema.
/recipes
  • Runtime-created items can be recipe results through their authoring paths.
  • Recipes can be added to selected crafting-station rows and menu categories.
  • Authoring supports consumed items, created items, extra outputs, counts, crafting audio, crafting skills, and notification behavior.
  • Separate recipe mods can expose the same authored item at different stations without changing the item definition.
/players — persistent profiles and selectors
  • Added persistent /players rules to the runtime lifecycle, checked after startup and while players join or respawn.
  • Replacement player pawns receive their profiles after respawn.
  • Original player values are captured as baselines to prevent repeated multiplier drift.
  • Matching rules compose in deterministic mod, file, and array order.
  • Selectors include PlayerName, PlayerNames, PlayerGuid, PlayerGuids, *, and stable first-seen connection slots *1, *2, and subsequent *N.
  • GUID matching is authoritative when a GUID selector is supplied.
/players — adjustments and attributes
  • Added Scale; health/max health; defense/damage; stamina/max stamina; walk/run speed; carry weight/max carry weight; poison resistance; stamina recovery; and physical, magical, and ranged attack/defense multipliers.
  • Added the documented BaseHealth, Magic/Magical, and Range/Ranged aliases.
  • Added AttributeMultipliers for normalized named attribute assets/classes.
  • Added Attributes operations: Set, Add, and Multiply against captured baselines.
  • Attribute identifiers accept normalized FModel object paths, data-asset names, generated-class names, and common naming prefixes/suffixes.
  • Invalid, missing, or ambiguous attributes fail safely and are reported.
/players — appearance
  • Added body type, face/head, hair, facial hair, skin tone, hair color, eye color, and eyebrow color selection.
  • Appearance values may reference vanilla rows directly.
  • Added source manifests for custom appearance packs; all enabled sources register before player rules are parsed so cross-mod references are independent of mods.txt position.
  • Custom sources require safe vanilla fallback rows.
  • Applied appearance provenance is saved under RuneSchema/player-data.
  • When an appearance source is disabled, RuneSchema can reconcile the affected player back to its recorded vanilla fallback.
/spawns
  • Added uniform numeric and per-axis vector scale for persistent actors and AI; scale reapplies as persistent or streamed AI is created.
  • Added optional DropIncreasePercent, controlled separately from actor scale.
  • Added per-instance top-level DisplayName, allowing two instances of the same AI class to have different names.
  • Retained native PowerLevel naming and added bounded HealthMultiplier and DamageMultiplier.
  • Added LootRow selection for native /raw-authored enemy loot routes and additional drops.
  • Added CharacterProperties and ComponentProperties for exact FModel-derived reflected fields.
  • Retained persistent actor IDs, duplicate prevention, variants, progress conditions, roam, sentry, perception, distance, tag, respawn, activation, and advanced reflected-property controls.
Example authoring packages
  • Added a ten-cape example pack based on the White Adventurer's Cape.
  • Each example cape has a unique asset path, persistence ID, internal name, display name, flavor text, and wearable-equipment row.
  • Added ten new DT_WearableEquipment rows with different defensive profiles and ten Mystic Forge crafting recipes.
  • Added four connection-order player profiles demonstrating health, stamina, scale, movement, carrying, recovery, attack, and defense roles.
  • Added disabled templates for arbitrary attributes and player appearance.
  • Added a named spectral-zombie spawn example and expanded example READMEs with supported fields, ranges, conflicts, deterministic composition, use cases, and testing guidance.
Compatibility and safety
  • Retains the established RuneSchema loader directories and 0.6.0 authoring model.
  • Does not import unrelated later quest, event, dialogue, NPC, resource, or replacement spawn-scheduler systems.
  • Does not allow temporary/session-generated item identities, clone identity inheritance, patch-based identity mutation, or unrestricted cloning of arbitrary complex DataAssets.
  • Invalid operations are rejected or logged instead of silently changing identity state.

Testing status

The Windows Game__Shipping__Win64 DLL builds successfully against the pinned UE4SS dependency, and package plus embedded example JSON validation completes without errors.

In-game testing remains recommended for multiplayer connection ordering, each player attribute family, appearance refresh/fallbacks, custom overhead AI names, crafting registration, item save persistence, and multi-mod conflict order.
