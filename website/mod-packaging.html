CANONICAL AUTHOR METADATA

Make your mod understandable.

ID.txt gives Dragonwilds Sync a safe, portable identity for your mod and its custom items. This guide explains every line, exactly how the parser treats it, and how icons travel from a normal mod archive into application-generated .rsdwl packages.

Build ID.txtHOTLOAD = YESDrop-in readingPackage files
Nothing in ID.txt executes.

It is declarative display and registry metadata. Unknown instructions are ignored, secret-like values are stripped, and URLs are shown as links only.

Only ModId and a useful Name should be considered essential author hygiene. The remaining lines add versioning, presentation, runtime behavior, links, and item records.

1

Comment

Any line beginning with #, ;;, or // is ignored. Use comments for humans, not instructions.

IGNORED
2

Schema declaration

Documents the contract version. The current parser recognizes the file by its fields and ignores this value during normalization.

RECOMMENDED

Stable mod identifier

Use one durable ID and never recycle it for a different mod. Maximum 160 characters. It also becomes the default ModId on Item rows.

CORE IDENTITY
4
Name: Example Community Mod

Display name

The readable title shown on placards and repositories. Maximum 200 characters. Aliases accepted: ModName and Title.

DISPLAY

Release version

Your public version string, up to 80 characters. Keep it sortable and change it when users receive a new payload.

VERSIONING

Use when the package metadata or item definitions change independently of the public mod version. Aliases: Rev and MetadataRevision.

MERGE HINT

Author: Your Modder Name

Attribution

The creator name shown to users, up to 200 characters. Creator, By, Modder, and Authors are accepted aliases.

ATTRIBUTION

RuntimeRole: both

Where the mod belongs

Choose exactly client, server, both, or tooling. Unknown values safely become both. host/dedicated normalize to server.

PLACEMENT
9
HOTLOAD = YES

Live-edit promise

The canonical writer emits exactly HOTLOAD = YES or HOTLOAD = NO. The parser also accepts HotloadCapable, Hotload, LiveEditing, or LiveEdit, with either : or =. True values are YES, true, 1, on, or enabled.

BE HONEST
10
Description: One plain sentence...

Short explanation

Plain display text, never HTML or code. Maximum 4,000 characters. Aliases: About and Summary.

DISPLAY
11
Tags: QoL; Storage

Search and grouping

Separate tags with semicolons or commas. Duplicates are removed case-insensitively; at most 24 tags are kept, each up to 40 characters.

MAX 24
12
Nexus: https://...

Author links

Any field containing an http:// or https:// value becomes a labeled link. At most 12 unique links are kept. Non-web schemes are ignored.

URL ONLY
13
Item: { ... }

One custom-item record

Repeat one line per item, up to 4,096. JSON is preferred; pipe-separated key=value pairs are also accepted. See the item-field table below.

NO CONVERTER REQUIRED

Drop a simple ID.txt in with the mod.

A normal folder, ZIP, or manually packed .rsdwl can carry the file directly. Dragonwilds Sync discovers and reads it during staged installation and every mod inventory scan; .rsdwl is not required for basic mod identity or HOTLOAD detection.

01

Stage safely. Sync opens the normal archive in staging and never executes metadata.

02

Find the effective root. Payload classification identifies the actual UE4SS, RuneSchema, or PAK mod folder inside optional wrappers.

03

Discover identity. At that root, Sync searches case-insensitively for canonical ID.txt, then legacy identity.txt and identities.txt.

04

Read within bounds. The file must be at most 512 KiB and is decoded as UTF-8 with replacement for malformed bytes.

05

Normalize recognized fields. Comments and section labels are skipped; aliases, :/=, tags, URLs, runtime role, items, and booleans are bounded. Unknown non-URL fields are ignored.

06

Apply safe metadata. Placards, tags, repositories, Item Editor, and Spawner consume the normalized record. Nothing in the file is launched as code.

CUSTOM ITEMS

Inside each Item: line

ITEM NameInternal searchable name

Example: ITEM_ExampleSword. Aliases include Item, Name, and ITEM_NAME after normalization.

PersistenceIDThe merge identity

The exact stable save/runtime identity. If two sources declare the same value, Dragonwilds Sync treats them as the same item.

DisplayNameHuman-facing label

Optional but strongly recommended. Alias: Label.

IconPortable relative icon path

Use a path inside the package such as items/icons/example-sword.png. Never use a machine-absolute path.

AssetPathRuntime asset location

The Unreal content path used to resolve or spawn the item, up to 1,000 characters.

ModIdOwning mod

Optional per row. When omitted, the file-level ModId is copied into the normalized item record.

HOW SYNC READS IT

From disk to placard and Spawner

  1. Discover.The launcher searches the effective mod root case-insensitively for ID.txt, then legacy identity.txt and identities.txt.
  2. Bound.Files above 512 KiB are rejected. Text is read as UTF-8 with invalid bytes replaced rather than executed.
  3. Parse.Blank lines, comments, and section headers are skipped. Both Key: Value and Key=Value work.
  4. Normalize.Aliases become canonical fields; booleans, runtime roles, links, and tags are bounded and deduplicated.
  5. Sanitize.Keys resembling passwords, secrets, tokens, credentials, sessions, or server/admin keys are removed. dws-secret:// values become blank.
  6. Merge items.Item Editor, Spawner, profile bundles, and WebGUI converge on PersistenceID; item-name and display-name searches remain available.
  7. Present.The mod receives name/version/author/link metadata, tags, runtime badges, and normalized custom-item/icon records. No line is run as a command.
ZIP AND RSDWL

One clear mod package format

A mod-author .rsdwl is a ZIP-readable archive with one recognizable mod folder. It uses the same effective-root rules as a normal mod ZIP, so the package shown on the left is now the format to follow everywhere.

AUTHOR PACKAGE

Recommended .rsdwl layout

ExampleMod.rsdwl
`-- ExampleMod/
    |-- ID.txt
    |-- mod payload...
    `-- items/
        |-- manifest.json
        |-- icon-manifest.json
        `-- icons/*.png

Build a normal ZIP with this layout, then use the .rsdwl extension. The payload may be UE4SS, RuneSchema, or PAK content. Keep ID.txt beside the effective payload root and keep item icons under package-relative paths.

WHAT SYNC DOES

Inspect, identify, and install

  1. Opens the archive in a safe staging area.
  2. Unwraps a single outer download folder when present.
  3. Finds ID.txt case-insensitively at the effective mod root.
  4. Classifies the real UE4SS, RuneSchema, or PAK payload.
  5. Imports declared custom items and package-relative icons.

No application export manifest is required for an author-packed mod. The mod folder and its payload remain the source of truth.

ZIP and .rsdwl now share the same authoring model.

Use .zip while testing or publish the same ZIP-readable structure as .rsdwl. Do not add the older PackageManifest/ or ModInfo/ wrapper shown in previous guidance.

SEPARATE LAUNCHER EXPORT

Profile packages are application-owned

When Dragonwilds Sync exports a profile package, the launcher creates its own signed and checksummed root manifest.json with profile/, worlds/, and items/ payloads. That profile bundle is generated by Sync and is not the format mod authors should hand-pack. Connected-world passwords and administrative credentials are always excluded.

ICON CHECKLIST

Icons that survive another machine

01

Use PNG, JPEG, WebP, or GIF. Keep a custom item icon at or below 2 MiB.

02

Store it under your mod, preferably items/icons/.

03

Reference it with a forward-slash relative path; never C:\... or /home/....

04

Let Sync generate icon-manifest.json; it records path, SHA-256, and media type.

05

Keep each icon inside the import root. Paths containing escape traversal are rejected.

06

Export through Sync so package checksums and icon payload records are generated together.

Important boundaries

  • Scale changes size only; it does not automatically change drops, health, damage, navigation, or animation.
  • Drop multiplication has its own master switch and only affects supported live ItemsToDrop rows.
  • The compatibility report is advisory and cannot identify every semantic gameplay conflict.
  • Generated schemas and FModel snippets remain drafts that require author review.
  • Explicit identity values must be unique and stable; blank or omitted values preserve the loaded/default identity.
  • Load-order changes apply on the next RuneSchema load or restart.
